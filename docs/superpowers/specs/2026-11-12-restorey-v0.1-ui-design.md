# Restorey v0.1 UI — design

Plan 2 of v0.1: the user interface on top of the merged v0.1 engine (PR #1, `a45d1c8`). The product spec is
[2026-11-09-restorey-design.md](2026-11-09-restorey-design.md) ("the product spec"); this document narrows it to what the v0.1
UI must do and records the decisions made with the owner on 12 Nov 2026. Where the two disagree, this document wins for
v0.1, and the product spec is updated to match (see "Changes to the product spec").

Mockups (all approved by the owner, 12 Nov 2026):
- [v0.1-setup-flow.html](../../mockups/v0.1-setup-flow.html) — first-run setup, step by step
- [v0.1-settings.html](../../mockups/v0.1-settings.html) — Settings window (the Network section was agreed in words afterwards; it isn't drawn)
- [v0.1-menu-states.html](../../mockups/v0.1-menu-states.html) — menu bar states beyond the earlier approved idle and in-progress menus
- [menubar-and-restore.html](../../mockups/menubar-and-restore.html) — the earlier approved idle and in-progress menu (the restore window in it is v0.2)

## 1. Intent

The engine runs backups; today the only way to drive it is the developer window. Plan 2 replaces that with the real app,
so the owner can move their Mac's real backups onto Restorey.

**Success, in the owner's words:** "when setup works end to end and backups just run quietly." Concretely: on a Mac with
no Restorey state, the signed app takes the owner from first launch to a running first backup without the developer
window, Terminal or the README, and from then on the menu bar is the only thing they look at, and only when something is
wrong.

## 2. Goals

1. A guided first-run setup that ends with the first backup running (§4).
2. The menu bar in every state the agent can be in, live, for one or several plans (§5).
3. A Settings window for editing plans, adding plans, history, schedule and bandwidth (§6).
4. The recovery kit, before any first backup and on demand afterwards (§7).
5. The plan-2 carry list from the alpha (§8).

## 3. Non-goals and anti-goals

**Non-goals for v0.1:**
- The restore window (v0.2). "Restore Files…" opens a sheet with this plan's restic restore commands (§5.4).
- Cold plans and the thaw flow (v0.3); the plan editor has no hot/cold choice.
- ntfy, Pushover and webhook alerts, `--read-data-subset` and test restores (v0.1.x). The Alerts section (Schedule tab) offers only
  notifications, the check-in URL and the "no successful backup in N days" threshold.
- Sparkle, the Homebrew cask, release automation (plan 3).
- Removing the developer window. It stays in Debug builds as a tool; Release builds don't show it (builder may hide it
  behind a build setting).

**Anti-goals — failure even if it works** (from the product spec §4, applied to the UI):
- A backup that has quietly stopped while the menu says all is well. Every state the agent reports reaches the menu.
- A failure that looks like a warning: missing Full Disk Access, a wrong password, an unreachable agent are errors, never
  "some files skipped".
- A repository nobody can open: no plan backs up before its recovery kit is confirmed.
- Noise: a healthy plan shows nothing that asks for attention. "Backed up at <time>" is the whole story.

## 4. First-run setup (decided, mockup `v0.1-setup-flow.html`)

A setup window opens on first launch, and whenever no plan exists. Steps, in this order (owner's order):

1. **Permissions — all of them, first.**
   - *Move to Applications*, if the app isn't running from `/Applications` (screen comes before anything else; the
     engine's `/Applications` check already exists). The button moves the app there itself and relaunches it (my call),
     asking for an administrator password if macOS needs one. This screen only appears before any agent is registered,
     so no backup can be running. If `/Applications` already has a Restorey, the screen says so and offers to replace
     it only when that copy's agent isn't registered; otherwise it asks the user to quit and replace it by hand.
   - *Full Disk Access*: explains why, opens the right System Settings pane, and is checked from the agent's context
     (the agent's own probe, product spec §5.7), not the app's. While missing it shows a draggable tile with the app's
     icon and name (the app bundle, as a file URL: the agent runs under the app's TCC attribution, spike H1), the
     caption "Drag this into the list, then switch it on." and the one-line why "Without it, Restorey can't back up
     Mail, Messages, Safari and other protected folders."; granted, a green tick and "Full Disk Access is on" and no
     button (Task 16c, owner-approved 17 Nov 2026, from the Arq study). Granting it makes macOS quit the app; on relaunch setup
     reopens at this step with it ticked.
   - *Notifications*: requested through the agent (it posts the alerts).
   - Continue is enabled when Full Disk Access is granted. Notifications may be declined (the menu then shows the
     "Notifications are off" warning).
   - Location is **not** requested here (§6.3).
2. **Where backups go.** B2 (default), S3, or another restic location (raw repository string plus environment names).
   B2 and S3 have guided forms with a link to the provider's documentation for making a bucket and a key. "Check"
   validates the credentials and looks for an existing repository at the address.
3. **Repository password.** Two cases, decided by step 2's check:
   - *Nothing there:* a generated password (show, copy, or type your own) and an explicit **Create new repository**
     button. Never initialise automatically (product spec §5.4).
   - *A repository is there:* "312 snapshots from 3 Macs" — enter its password. Restorey then adopts it (product spec §5.4):
     sources pre-filled from the latest snapshot for this host label, the host-label and new-group warnings, and the
     opt-in for applying retention to existing snapshots.
     **(Task 14b)** The opt-in is a switch, "Apply this plan's retention to existing snapshots from this Mac", off by
     default. On, "Use This Repository" adopts, then previews (`forget --dry-run`, no lock, nothing recorded) and asks
     in a destructive alert, Cancel the default button (Return; Escape cancels too): "Remove N snapshots from before
     Restorey?", then, kept short so the sheet fits the setup window (fix round 2), "Retention keeps K of the T
     snapshots of these folders from this Mac, other tools' included; the rest go after the first successful backup. Other Macs and folders aren't
     touched. Prune frees the space later. (or: Prune is off: the data stays.) This can't be undone." "Before
     Restorey" means taken no later than the adoption, which setup records (fix round 1); the destructive button
     reads "Remove N Snapshots" and is never the default. The confirmed IDs are kept
     in the setup progress; Done hands them to the agent, which removes them after the plan's first successful backup.
     Nothing beyond retention, or Cancel, keeps the step ("The repository is ready") with the switch and one line
     saying nothing will be removed.
4. **Recovery kit** (§7). Required in both cases. Continue needs the "I've saved it somewhere other than this Mac" tick.
5. **What to back up.** Home folder by default, add folders or drives, the default exclusions summarised in one line
   with "Review exclusions…" (folders, file types, one file system — product spec §5.7). For an adopted repository, the
   pre-filled sources are shown here.
6. **Schedule.** Interval (hourly default), battery rule, retention (shown, editable), optional check-in URL. The plan's
   upload limit is not on this screen (Settings only, default None).
7. **Done.** "Start first backup" saves the plan, starts the first run, and shows its live progress. The window can be
   closed; the backup carries on and the menu bar shows it.

Setup state survives a quit at any step: relaunching returns to the step reached, with entered values kept (secrets
excepted unless already saved to the Keychain).

"Add Plan…" in Settings runs steps 2–7 in a sheet or window.

## 5. Menu bar (decided, mockups `menubar-and-restore.html` and `v0.1-menu-states.html`)

The approved idle and in-progress menus stand. Additions approved on 12 Nov 2026:

- **Native menu (Task 17d, owner-approved polish pass, 17 Nov 2026; audit P2, P4, P5):** standard AppKit items, not
  hand-drawn rows. Each plan is a section headed by its name (`NSMenuItem.sectionHeader(title:)`, macOS 14); its status
  item has the status as the title, one short detail and the destination as the subtitle (`NSMenuItem.subtitle`,
  macOS 14.4), and a symbol for the state (tick, dashed circle before the first backup, up arrow, pause, or the
  multicolour warning triangle or error octagon), always visible (`preferredImageVisibility = .visible`, macOS 27,
  which otherwise hides menu item images). A problem is one item named for its fix, the problem as its subtitle and
  why it matters as its tooltip: problems with the whole Mac at the top, a plan's own in its section. No indented items:
  "Don't Show This Again" and "Show Details…" are items of their own in the plan's section. Menu lines are short (about
  45 characters) and never restic's raw error; the full reason is the item's tooltip and the plan's Overview, one click
  away. Every item in a group has a symbol or none does (HIG Menus).
- **Pause and Cancel Backup (v0.1.1):** both appear only while a backup runs (Pause: owner, 20 Nov 2026, "you can't
  pause something that's not running"). Pause is a submenu of its length: For 1 Hour, For 4 Hours, Until Tomorrow (one
  submenu level, HIG Menus). With several plans backing up the submenu has a section header, All Plans, and the three
  lengths, then a header per running plan (its name) and its three lengths; each length says what it pauses for
  VoiceOver ("Pause Photos for 4 hours"), since a header isn't read with its items. Cancel Backup follows Pause: a
  plain item when one plan runs, otherwise a submenu of All Plans, a separator and one item per running plan. It stops
  this run only (the agent's `cancel`), and never moves the schedule.
- **Several plans:** one section per plan. Back Up Now acts on all plans when clicked, or on one plan from a
  submenu, which stays enabled when none of its items can act (HIG Menus: "Make sure a submenu remains available even
  when its nested menu items are unavailable").
- **Option-click (Task 17d, audit T1):** a Diagnostics section before Settings: the app's version, the background
  process's version or state, Show Last Run Log, Show Logs in Finder, Copy Diagnostics. Nothing destructive, and nothing
  only reachable there (HIG: a dynamic item mustn't be the only way to do something). It comes with the click, as in
  Apple's own extras.
- **Tooltip (Task 17d, audit T9):** the status item's tooltip gives the state in words, updated with the icon:
  "Restorey — Last backup at 14:16", "Restorey — Backing up", "Restorey — Paused", or the worst problem (naming its plan
  when there are several; a sentence that already starts "Restorey" isn't prefixed again). Remade when the calendar day
  changes, so a relative day never goes stale.
- **Icon** shows the worst state across all plans as the system's drive symbol (`externaldrive`) with the state as a
  badge in its bottom-right corner (owner, 20 Nov 2026, replacing the 17 Nov "Layers" glyph, whose "!" over two faded
  dashes was hard to read; spec `2026-11-20-menu-bar-icon-design.md`). Up to date, a tick (`checkmark.circle.fill`),
  only when every plan has a backup that saved the data and nothing ranks higher; backing up, an up arrow; paused, a
  pause mark; needs attention, "!"; a problem that stops backups, "×" (all `*.circle.fill`). Nothing to report yet
  (`StatusIconState.idle`: a plan before its first backup, or Restorey connecting to or updating its background
  process) is the drive alone. The outline drive in every state, error included; one 22 × 16 pt canvas, the badge 72 %
  of the drive's height over a 1.5 pt cleared gap. Template images (monochrome menu bar, owner, 12 Nov 2026), drawn
  from SF Symbols at run time by `App/StatusIcon.swift`. Not the Time Machine clock badge (audit P12).
- **App icon** "Snapshots" (owner, 17 Nov 2026; audit F10): the same three layers in white on teal, the newest with an
  up arrow lifting out of it, as a layered Icon Composer document so macOS renders the default, dark, clear and tinted
  appearances. The app and the agent (whose icon notifications show) both carry it. Original artwork.
- **Paused:** "Paused" with the pause symbol, never "Failed", with the auto-resume time ("Resumes by itself at 15:00"). The
  grey status words went with the hand-drawn rows (Task 17d): a standard item's title is in the label colour, and the
  symbol carries the state.
- **Warnings and errors**, each with its fix (Task 17d wording: the item is the fix, the problem its subtitle):
  - errors: "Allow Full Disk Access…" (Full Disk Access is missing), "Restart Backups" (Backups aren’t running), "Show in
    Settings…" (Restorey can’t read its settings), a plan whose backup failed (with "Show Details…"), "No successful
    backup in N days";
  - warnings: "Turn On Notifications…" (Notifications are off), "Add Check-In URL…" (No off-Mac monitoring), skipped runs
    with their reason (drive not connected, on battery, etc.), files that couldn't be read.
- **Updating:** "Finishing the current backup before updating".
- **Live:** the menu updates while open (product spec §5.1).
- **Restore Files…** (v0.1) opens a sheet with the selected plan's restic restore commands, each with a copy button,
  matching the recovery kit's "restore without Restorey" section. The commands carry the **real** repository address,
  password and backend credentials (owner, 12 Nov 2026), shown as password dots. Holding **Option** reveals them while
  held (owner's idea). Revealing or copying a secret first asks for Touch ID or the login password, once per opening of
  the sheet (my call: the same gate as "Show Recovery Kit…", since the sheet is one click from the menu). In v0.2 this
  item opens the real restore window (browse snapshots, restore files); the commands sheet moves into it as "Restore
  without Restorey".
- **Destination line** (approved idle menu): provider · bucket · repository size. A plan named after its repository
  (setup's default, such as "restic · sftp") or named as the line reads, ignoring case and spacing, shows only the size,
  so the section doesn't say the place twice (Task 17d, audit P3). The size comes from a `restic stats
  --mode raw-data` run in the plan's repository queue after each prune (about weekly) and after adoption, shown with its
  age ("486 GB, 3 days ago"); until the first one, the line shows provider and bucket only (my call: hourly size checks
  would add requests and lock time for a number that changes slowly). With several plans, each plan's line carries its
  own destination under its status.
- **Standing notes** (my call, from product spec §6.2): "No off-Mac monitoring" is a note the user can dismiss per plan;
  once dismissed it stays dismissed (stored with the plan, owned by the agent) and the icon ignores it. Before dismissal
  it counts as a warning. "Notifications are off" can't be dismissed: notifications are the only alert channel on the
  Mac, and the spec makes them always on. Each warning and error in the menu counts toward the icon's worst state.
- **Unfinished plans** (my call): a plan saved during setup or "Add Plan…" whose recovery kit isn't confirmed shows in
  the menu as "Finish Setup…" over "Setup not finished" in its section (warning) and in Settings with the same button, which reopens setup
  at the step reached. Setup opens on launch while any plan is unfinished, not only when no plan exists. An unfinished
  plan can be deleted like any other.
- **Shortcuts actions (Task 17e, owner-approved polish pass, 17 Nov 2026; audit T2):** the menu's actions as App Intents,
  in the Shortcuts app and Spotlight (macOS 26 Spotlight actions) with no other UI; not Siri voice, which Apple says
  isn't available for App Shortcuts on macOS (Developer Forums thread 764609): **Back Up Now** (a plan, or none for every plan), **Pause Backups**
  (with a Length: For 1 Hour, For 4 Hours or Until Tomorrow, the menu's titles; the dialogs say "…for an hour.", "…for 4
  hours." or "…until tomorrow."), **Cancel Backup** (a plan, or none for every running plan; refused with "There’s no
  backup to cancel." or "“<name>” isn’t backing up."), **Resume Backups**, and **Get Last Backup**, which
  returns the plan's (or, with none, the newest) backup time and outcome in the History list's words as values a
  shortcut can use, plus a summary sentence. The App Shortcuts' phrases name the app, as App Intents requires. They run in the background in the app (no extension: only the app talks to the agent),
  through the same `AgentConnection` and from the same `MenuContent` as the menu, so an action is refused exactly
  where the menu's item is dimmed, with a sentence in the menu's words saying why (`ShortcutRules`). No secret crosses
  an intent; Get Last Backup changes nothing. **(Fix rounds 1 and 2)** The windows Restorey opens by itself at launch (setup,
  the move screen, Settings for a hidden icon) open on its first activation, not the launch, each once per run, so a
  launch that doesn't activate it (`open -g`, an action run in the background) shows nothing until the person comes to
  it (`LaunchWindowGate`; not yet checked against a real Shortcuts launch). A multi-plan Pause or Resume that partly
  fails names each failed plan and those that changed.

## 6. Settings (decided, mockup `v0.1-settings.html`)

A toolbar window with four sections: **General, Plans, Network, History** (owner: "B for the overall settings window, but
selecting plans gives you A").

Window behaviour (UI polish pass, 17 Nov 2026, from the HIG's Settings page): the window's title is the pane showing
("General", "Plans", "Network", "History"); it has no Minimise button, a dimmed Zoom button, no full screen and no tabs,
yet stays resizable; it opens at the section last viewed (kept in `UserDefaults`, the section only, not the plan or tab)
and at its saved frame (autosave name `RestoreySettings`; centred when none); and its close button shows the edited dot
while a plan or the Network section has unsaved edits (the state the close and quit questions use). Esc closes a sheet
that has only a Done button, as Done does. The About panel shows `NSHumanReadableCopyright` and `Credits.rtf`: restic's
BSD 2-Clause licence verbatim and the EFF word list's attribution.

Layout (UI polish pass, Task 17c, 18 Nov 2026; HIG Settings, Layout, Tab views, Lists and tables, Buttons, Steppers):
every pane is a grouped form (`.formStyle(.grouped)`, as System Settings): a setting per row with its label leading and
its control trailing, related rows in sections, explanations in the sections' footers. Number fields are right-aligned
in digits of one width with a stepper beside them (validation unchanged). The window keeps its measured minimum width
(at least 760) and its 520 minimum height; long pages scroll inside their form.

### 6.1 General
Open at login, Full Disk Access (the §4 tile while missing, a tick when on; the menu banner's Open System Settings opens this pane beside
System Settings) and notification status (with fix buttons), the status and version of backups in the background, logs
(Show in Finder). While Full Disk Access is missing it is a section of its own at the top, the why, the tile and the
button across the form's width (Task 17c); granted, it is one row with the others.

### 6.2 Plans
A bordered list of plans, each with a symbol for where it backs up, with the standard square + (Add Plan…, §4 steps
2–7) and − (Delete Plan…) buttons under it, as Mail's Accounts and Users & Groups have (Task 17c; the translucent
sidebar and the Save bar's Delete Plan… are gone). Delete and the row's context menu delete too. **(Task 17e, audit
T4)** The row's context menu has the menu's Back Up Now, Resume (while paused), Pause (a submenu of the three lengths)
and Cancel Backup (both while it runs) and Restore Files… for the plan,
enabled as the menu's items are, then Show in History (History filtered to the plan, as the menu's "Show Details…"),
then Delete Plan… behind its confirmation: only actions that exist elsewhere. Each plan has six
tabs: Overview, Folders, Schedule, Storage, Retention, History, as a segmented control centred above an unboxed grouped
form, the way System Settings switches one pane's sub-pages (Trackpad, Sound; owner's decision, Task 17c fix round 1,
in place of a bezelled tab view that boxed the form's cards). The Save bar stays under every tab, dimmed where nothing
is edited, so the page keeps its height. The list's symbol is the repository's place (`Repository.place`): cloud for a
storage service, a server for SFTP or a REST server, a drive for this Mac. Until Task 17c there were seven, What, Keep and Alerts
among them: What became Folders and Keep became Retention (labels that say what the pane holds), and Alerts became a
section of Schedule.
- **Overview** (owner, 15 Nov 2026) — first, and where a plan opens from the sidebar or the menu's plan line (a route
  that names a tab, such as Alerts for "Add Check-In URL…", keeps it). A headline with the plan's state only, and the menu's reason
  under it where it has one (a failure's or stop's cause, what needs attention, a backup's progress). Headline words
  (owner ruling R1, 15 Nov 2026): "Up to date", "Backing up — 42%" (or "Backing up" before the first progress, and while restic is still counting the files, Task 16e),
  "Paused", "Backup failed", "Stopped", "Needs attention" (the menu's line has a warning or error, given as the reason),
  "Waiting for a new recovery kit", the menu's "No successful backup in N days", "No backup yet". The headline is
  in Headline (the plan's name above it is Title 3 Semibold) and carries a tinted symbol only when the plan itself
  needs attention (never for a menu banner such as "No off-Mac monitoring"), and then it or its reason says why; the
  words stay in the label colour. No plan name or repository label in it, and no times: those are only in the **Last
  backup** row ("Today at 17:10", "Yesterday at 09:05", "9 Nov at 09:05"; "Failed" under it while the menu shows a
  failed backup; "None yet") and the **Next backup** row ("Today at 18:10", "Tomorrow at 09:00"; "When the pause ends"
  under the time a pause ends). Then the menu's Back Up Now, Pause (while a backup runs; a pull-down menu button of the
  three lengths), Cancel Backup
  (while a backup runs, beside Pause), Resume (while paused) and
  Restore Files…, enabled as the menu's items are and asking the agent the same way. It follows the agent live.
  **(Task 17c)** The actions sit under the headline, in its section: Back Up Now in the prominent style at the trailing
  end with Pause or Resume beside it, Restore Files… at the leading end; the times follow in their own section. The
  Overview's Revert and Save stay dimmed, since nothing there is edited, unless a sheet left edits waiting (History
  likewise).
- **Folders** (was What) — the plan's name, sources, exclusions (folders, file types, one file system), with the product spec's warnings when sources or
  the host label change (new snapshot group). **(Task 17e, audit T3)** Folders and drives dragged from Finder onto the
  sources list or the exclusions list are added by the add button's rule (only folders and drives; nothing listed
  twice; `FolderDrop`; a link is judged where it leads, so a link to a folder is added as the path chosen), with the
  list ringed in the accent colour while the drag is over it and what was left out said
  under the list; Delete (⌫ or ⌦) removes the selected rows as Remove does; a source's context menu has Show in Finder
  and Remove. Setup's sources step shares the list.
  **(v0.1.1, Task 1: folder rules)** The sources list also keeps three rules, compared by whole path components and by
  where a link leads (read by `FolderDrop.look` off the main actor through `LinkResolver`, 10 s deadline, one look
  outstanding; past it, by the paths as written; v0.1.2, L157): (1) a folder inside a listed one is refused, "“Downloads”
  is already included in your home folder." (or "“Trips” is already included in “Pictures”.", or "2 folders are already
  included in folders in the list."); (2) a folder holding listed ones is added and takes them off the list, with a note
  under the list ("Your home folder includes “Downloads” and “Documents”, so they were taken off the list."; one:
  "“Pictures” includes “Trips”, so it was taken off the list."; three or more: "… includes 3 folders that were in the
  list, so they were taken off it."); (3) when the plan's repository is a local folder (`Repository.localFolderPath`),
  that folder is refused ("“repo” is where this plan’s backups are kept, so it can’t be backed up."), so is a folder
  inside it ("“data” is inside the folder where this plan’s backups are kept, so it can’t be backed up."), and a folder
  holding it is added with the note "This plan’s backups are kept inside “Disk”, so that folder is always left out." The
  backup always excludes the repository's folder (the path as given and, if different, where a link leads), and a plan
  whose source is inside its repository fails validation ("“data” is inside this plan’s backup repository. Choose a
  different folder."). Validation compares the paths as written (`SourcePaths.containsByPath`, no disk access, since the
  agent runs it on every status); saving a plan also follows links. A plan v0.1 saved with such a source shows "Stopped"
  with that reason on its menu line, page and sidebar note, raises the settings alert, and its Folders tab shows the
  same sentence under the list until the folder is removed. With no repository yet (setup), rule 3 is skipped. The note
  of rules 2 and 3 shows under the list as explanatory text (a refusal stays a warning), and the next change to the list
  clears it. When the repository's local folder is inside a source (by path: the sheet asks on every render), the
  Exclusions sheet lists it first, non-selectable, with the trailing caption "This plan’s backups" (VoiceOver: "<path>,
  this plan’s backups, always left out"); it is display only, never in the plan's `exclusions`, and Remove and Delete
  ignore it.
- **Schedule** — interval, battery rule, the plan's **upload limit (default "None")**.
  **(Task 16a)** Under the interval, one caption in secondary text: the plan's last backup and next run, worded and
  timed as the menu does (`MenuPresentation.scheduleCaption`): "Last backup at 14:16 · next at 15:16", "No backup yet ·
  first at 15:16", "… · paused, resumes by itself at 16:00", "… · skipped while on battery · next at …" (a battery,
  network, Wi-Fi or drive rule that skipped the last attempt; the agent's own update isn't named), "… · waiting for a
  new recovery kit". It describes the saved schedule; while the interval is changed and unsaved it ends "Next run time updates
  when you save." No new setting.
  **(Task 17c)** Then an **Alerts** section: the check-in URL and "no successful backup in N days" (the Alerts tab
  until then). The menu's "Add Check-In URL…" opens Schedule.
- **Storage** — the repository address is read-only: a different repository is a new plan, through "Add Plan…".
  Credentials and the repository password can be changed (e.g. a rotated B2 key). Saving a change to any of them pauses
  the plan's backups until a new recovery kit is saved and confirmed (owner, 12 Nov 2026: "pause until you save the
  kit"), because the saved kit holds the old values; the menu shows "New recovery kit needed — Save kit…" as a warning.
  This is the engine's existing behaviour (`savePlan` clears the kit confirmation). Host label editable with the
  product spec's new-group warning; pack size shown read-only; "Show Recovery Kit…" (§7).
- **Retention** (was Keep) — retention (the four counts as rows under "Keep", each with a stepper), prune toggle,
  forget cadence for adopted repositories.
  **(Task 16a)** Under the counts, a live plain-English summary of the policy in the form (`RetentionSummary`), from the
  rules `forget` is given (`--keep-hourly` … `--keep-monthly`): "Keeps the newest backup of each hour for the last 24
  hours that have one, each day for the last 30 days that have one, each week for the last 52 weeks that have one and
  each month for the last 120 months that have one. The rest are removed after each backup." (once a day for an adopted
  repository tidied daily). The wording follows restic 0.19.1's `forget` documentation: each rule counts the periods
  that *have* a backup, on natural boundaries (weeks Monday to Sunday), not the last N hours of wall time; a snapshot
  kept by any rule is kept; a count of 0 leaves the rule out; a form that doesn't read as a policy shows no summary
  (its own problem is shown). Beneath it, one quiet sentence on the weekly check: "Once a week Restorey checks the
  backup's structure. This downloads its index and folder lists, not your files, so it uses a little download
  allowance." Verified in restic 0.19.1 (`cmd_check.go`, `internal/checker`, `internal/repository/checker.go`): plain
  `check` makes a temporary cache (deleted afterwards, so nothing is reused between weeks), loads the snapshots, the
  index files and the tree blobs (folder lists), lists the pack files and compares their sizes with the index, and reads
  no data pack unless `--read-data` or `--read-data-subset` is given, which Restorey's weekly check doesn't. No sizes
  are stated, as they depend on the repository. No behaviour change.
  **(Task 14b)** Then **Earlier snapshots**: from a preview run when the tab appears (and after a save changes the
  folders, host label or retention, never on a redraw), one line per earlier group with something to remove —
  "Previous folder list ~/Old: 34 snapshots; retention would remove 12." and, for an adopted plan, "Before Restorey:
  40 snapshots from pepper; retention would remove 31." — each with "Apply Retention…", which opens the same
  destructive confirmation ("Remove N snapshots of the previous folder list?", "Retention keeps K of the T snapshots
  of ~/Old. Prune frees the space later. This can't be undone."). With nothing to apply, one line:
  "Nothing to apply: retention keeps every earlier snapshot." (or "No earlier snapshots from this Mac to apply
  retention to."). Unsaved edits disable the buttons, since the preview counts with the saved plan.
- **History** — the History table filtered to this plan.
- **Files that couldn't be read** (Task 16b, owner 17 Nov 2026; Arq study §3.1). After a warning backup, the Overview
  (under the reason) and the plan's History row have "Show…", a sheet of the files the backup couldn't read: the
  `~`-shortened path, why in plain words ("Restorey isn't allowed to read this" for operation not permitted or
  permission denied; "It was deleted while the backup ran" for no such file; otherwise restic's text), "Open in Finder"
  where the path still exists, and "Don’t Back Up", which adds `DefaultExclusions.pattern(forFolder:)` for the
  path to the plan's exclusions through the plan editor (unsaved until Save; the close and quit guard applies). The row
  then reads "Won't be backed up from the next backup" with Undo. A file deleted while the backup ran has no action, a
  path already excluded reads "Already not backed up", and the foot says "You can change this later in Folders → Review
  Exclusions…". The run record keeps the first 100 distinct archival items with a short reason (`unreadableItems`); the
  count stays exact and the sheet adds "and N more". Information only: no outcome, icon, alert or ping changes. The
  all-plans History list, which has no plan editor, doesn't offer "Show…".
- **Biggest additions** (Task 16d, owner 17 Nov 2026; product spec §5.7). Each backup that made a snapshot keeps the
  files that added the most to the repository and the folders whose files together did (`biggestAdditions`; a folder is
  up to three levels below the deepest source, stopping at a package such as `Photos Library.photoslibrary`). A plan's
  History row for such a backup has one quiet caption line under its detail, "Biggest additions: Photos.sqlite 1.1 GB,
  Lightroom Catalog.lrcat 312 MB, big.log 46 MB" (the three biggest files by name, sizes as the app writes them,
  `BiggestAdditionsText`), then " · folder listings 1.3 GB" when restic's folder listings added at least 1 MB (Task
  16f), with "Show…". The Overview shows the files' line (without the listings), with "Show…", under the Last backup
  row when the last backup added more than 100 MB to the repository (restic's `data_added_packed`), and not while that
  row shows a failure. "Show…" opens "Biggest additions": "Files added 4.3 GB to the repository, after compression.
  These added the most.", then Files (up to 10) and Folders (up to 5; a folder's size is its files' data and its
  folders' listings), each a `~`-shortened path with its size and "Open in Finder" while the path exists; when the
  backup changed more folders than are counted, a note says a folder may be missing. Under the lists, when the record
  has any: "Folder listings: 1.3 GB — restic records each changed folder's list of files; a change anywhere in a folder
  rewrites its list and the lists of the folders above it." A backup that added only listings (no file data, listings
  at least 1 MB) reads "Biggest additions: folder listings 1.3 GB" with "Show…", whose sheet says "No file added data to
  the repository; the folder listings below did." and leaves out the empty Files list; the Overview stays files-only. Nothing to name (no file added data and under 1 MB of listings, or a record from before Task 16d) means no line and no "Show…".
  Information only: no outcome, icon, alert or ping changes, and it is offered in the all-plans History list too, since
  it changes nothing. A row offering both sheets labels its links "Show Unreadable Files…" and "Show Biggest
  Additions…" (`HistoryPresentation.links`); a row with one says "Show…".
- A plan the agent has stopped shows "Stopped" and its reason on its page and under its name in the list, in the
  menu's words (live finding 3, 15 Nov 2026).
- Delete plan, − under the list (with the developer window's confirmation text: the repository and its snapshots aren't touched).

### 6.3 Network (owner, 12 Nov 2026)
Mac-wide rules, applying only to plans whose repository needs the network (product spec §5.5, Ruling R69):
- **Upload limit for the whole Mac** (default None).
- **Skip on a hotspot or in Low Data Mode** (moved here from each plan; default on).
- **Skip on these Wi-Fi networks:** a list of network names. macOS reveals the Wi-Fi name only with Location Services
  permission, so Restorey asks for Location **only when the user first adds a network to this list** (owner). Without
  permission, the list can't be used and says why.

How the two upload limits combine is the builder's call (§10).

**(Task 15, builder)** The section has Save and Revert as a plan's tabs do, and applies only the fields changed. A
Wi-Fi name is added trimmed, at most 32 bytes (an SSID's limit), and not twice ignoring case. Adding one while the
agent has never been asked asks for Location first and adds the name only once it is allowed; refused, the field
is disabled and the list says "Restorey needs Location permission to see Wi-Fi names." (with "Until then, backups
aren't skipped on these networks." when it holds any) and "Open System Settings". With Location Services off for the
whole Mac, macOS shows no prompt at all, so the agent checks for it before asking and answers at once, and the list
says "Location Services is off for this Mac, so Restorey can't see Wi-Fi names. Turn it on in System Settings →
Privacy & Security → Location Services." with the same button. Restricted (a configuration profile or Screen Time)
says "Location is restricted on this Mac, by a configuration profile or Screen Time, so Restorey can't see Wi-Fi
names. Whoever manages this Mac can lift it.", with no button. The pane asks the agent (`locationAccess`, never a
prompt) when it appears and whenever Restorey comes to the front. Closing Settings or quitting with unsaved Network
edits asks Save, Don't Save or Cancel, as for a plan (fix round 1). The decisions are `NetworkEdit`,
`WiFiNameAccess` and `UnsavedSettings`.

### 6.4 History
All plans' runs, newest first, with a plan filter and an outcome filter: time, plan, operation (backup, forget, check,
unlock), outcome, size and duration where known, and a link to the run's log. **(Task 17c)** A table with Time, Plan,
Step, Outcome, Added and Duration columns, sortable and resizable; a double-click opens a run's log, and its context
menu has Show Log, Show Log in Finder, Copy Outcome **(Task 17e)** and the row's sheets; ⌘C copies the selected rows as
text. A plan's own list drops Step (its outcomes name the step),
and the outcome and its reason wrap, so both are read in full at the window's smallest size. A backup that made a snapshot adds a
line naming its three biggest additions, with "Show…" for the lists (§6.2, Task 16d). A probe that finds no repository at an
address is the answer setup expects for a new one, not a failure, so it isn't listed under Problems (live finding 1). The plan filter is the menu's "Show
Details…" plan only when it opens History; History chosen in the toolbar starts with every plan (Task 15).

## 7. Recovery kit (product spec §7, unchanged in substance)

Shown in setup step 4, and later from the plan's Storage tab behind Touch ID or the login password. Contents: repository
address, repository password, backend credential names and values, host label, and the plain restic commands to restore
without Restorey. Offered, in this order: copy each field, print, save to a location the user picks (no default
location; a warning if the location is on the Mac's internal disk). Never written anywhere automatically.

## 9. Constraints

- macOS 27, Swift 6.4, Xcode 27; SwiftUI with AppKit where SwiftUI falls short (status item, Edit menu).
- Builds and tests on this Mac (`scripts/ci.sh`) and GitHub Actions; never birdseye.
- The helper's code-signing requirements are not relaxed (owner).
- Tests and CI never touch the real identity (Ruling R66).
- Australian English in all UI text; timestamps stored in UTC, shown in local time.
- Type, colour and wording (Task 17b, owner 17 Nov 2026; HIG Typography, Color, Accessibility and Writing). The system
  text styles at their default weights: a window, sheet or page title is Title 3 in its emphasised weight (Semibold),
  a section heading or status headline is Headline, an explanation under a control is Subheadline (never Caption,
  which is for short tags such as "Restorey's own"), and an error or warning is Callout. Text is in the label colours.
  What a status means is carried by a tinted symbol with its own shape (a triangle for a warning, an octagon for an
  error, a tick for a success, a minus for a run that didn't run), never by colour alone, and each symbol has an
  accessibility label; History rows have one per outcome. Buttons and menu items are in title-style capitalisation
  ("Add Plan…", "Show Recovery Kit…", "Don’t Back Up", "All Plans"), with an ellipsis only where more input follows,
  and every jump to System Settings is "Open System Settings". Headings and labels are in sentence case. Quotes and
  apostrophes are curly. "Agent" is not a word the person sees: it is "backups" ("Backups aren’t running", "Restart
  Backups", "Backups in the background" in General) or "Restorey's background process".
- Secrets never in config files, logs or the UI's model longer than needed (product spec §7).
- The engine's XPC protocol is versioned by the hello handshake; new calls follow the same pattern.
