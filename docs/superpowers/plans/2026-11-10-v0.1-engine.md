# v0.1 engine implementation plan (plan 1 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Restorey's backup engine: the core library, the background agent, and a minimal app shell that installs and watches the agent. The plan ends with the owner's real hot plan to a B2 test bucket backing up hourly from launchd, alerting through macOS notifications and a check-in URL, and surviving reboots, crashes and an N→N+1 update.

**Architecture:** Three products are built from one XcodeGen project. `RestoreyCore` is a Swift package holding all logic that can be tested without a GUI session: config, restic invocation, NDJSON parsing, process supervision, the per-repository queue, scheduling, alert policy and logs. Its integration tests run against a real restic binary. `RestoreyAgent.app` is the `LSUIElement` helper app from the spike. It runs as a LaunchAgent and owns the config, the scheduler, restic supervision, the secrets and the alerts. It also serves as restic's password and S3 credential helper. `Restorey.app` is UI only. In this plan it is a status item plus a Debug-only developer window, and plan 2 replaces both with the real menu bar and onboarding. The app and the agent talk over two XPC Mach services, one for the app and one for the helper, each with its own code-signing requirement.

**Tech Stack:** Swift 6.4 language mode with complete strict concurrency, macOS 27.0, Xcode 27.0, XcodeGen 2.46.0, Swift Testing, `NSXPCConnection`, ServiceManagement, Security (data protection keychain), UserNotifications, IOKit (power sources and power assertions), Network (`NWPathMonitor`), MetricKit, restic 0.19.1 and rest-server 0.14.0 (upstream release binaries), GitHub Actions on the `xcode-27` runner.

**Spec:** `docs/superpowers/specs/2026-11-09-restorey-design.md`. Read §4 (anti-goals), §5.1 (pause), §5.3–§5.7, §6, §7, §8, §10 and §12.5. The platform evidence is in `docs/spike-findings.md`. Its "Consequence for v0.1" column is binding on this plan. Working spike code that shows how to do registration, XPC, keychain and the helper is in `spike/`. Port from it, but don't import it.

## Scope

**In this plan:** everything in the spec's v0.1 row except the screens. That means the agent and scheduler, hot plans (B2 and S3 forms in the model, raw repository plus environment variables), adopting an existing repository, Pause, macOS notifications, the check-in URL, the heartbeat, the version handshake and agent restart, `restic check`, keychain secrets, the versioned config, the `/Applications` gate, persistent logs and crash diagnostics. The rule that a backup can't run before the recovery kit is confirmed is also in the engine.

**Plan 2 (UI, written after the mockups in `TODO.md`):** the menu bar with live progress and the multi-plan states, onboarding (Move to Applications with the quarantine strip, FDA, notifications, check-in URL), plan setup forms, the recovery kit sheet, "Show recovery kit", "Copy as restic command", "Send diagnostic report", and the Settings cache size with Clear.

**Plan 3 (release):** the signed and notarised DMG built by GitHub Actions on version tags with an App Store Connect API key, the changelog, the README's "restore without Restorey" section, and the release checklist with a real restore.

## Decisions made in this plan (builder's calls, spec §14)

- **Config storage:** two Codable JSON files in the agent's Application Support folder, `config.json` (plans) and `state.json` (run history). Each has a `schemaVersion` and runs through registered migrations. Writes are atomic. Only the agent writes them, and the app changes plans over XPC. This suits a handful of plans, is easy to inspect, and keeps one writer per file.
- **XPC:** `NSXPCConnection` with Codable payloads passed as `Data`, so the protocol needs no `NSSecureCoding` classes, as in the spike. There are two Mach services. `<agent label>` serves the app, with a requirement of app identifier plus team. `<agent label>.helper` serves the password and credential helper, with a requirement of agent identifier plus team. Live progress is pushed to the app through an exported client object on the connection.
- **Development identity (spec §9):** Debug builds use `com.jaydenkerr.restorey.dev`, `RestoreyDev.app` and `RestoreyDevAgent`. Release builds use `com.jaydenkerr.restorey`, `Restorey.app` and `RestoreyAgent`. No product name contains a space (spec §7, `credential_process`).
- **Re-notify back-off (spec §6.2):** notify when a condition is raised, then after 1 h, 6 h, and every 24 h after that while it holds.
- **Rescheduling:** after exit code 11, try the backup again in 15 min. After a skip, re-check at the next hourly tick, or on wake or volume mount.
- **Default pack size** for repositories Restorey creates on B2 or S3 is **64 MiB** (spec §5.3, approved by the owner). Adopted repositories pass nothing.
- **Time Machine exclusions:** v0.1 translates only the fixed-path exclusions in `/System/Library/CoreServices/backupd.bundle/Contents/Resources/StdExclusions.plist`, if that file exists on macOS 27. Per-item sticky exclusions (the xattr) are deferred and recorded in `docs/`.

## Global Constraints

- macOS 27.0 deployment target, Xcode 27.0, Swift 6.4 language mode, `SWIFT_STRICT_CONCURRENCY: complete`, hardened runtime on every target (spec §8).
- Release identities: app `com.jaydenkerr.restorey`; agent `com.jaydenkerr.restorey.agent`; launchd label and app Mach service `com.jaydenkerr.restorey.agent`; helper Mach service `com.jaydenkerr.restorey.agent.helper`; keychain group `$(AppIdentifierPrefix)com.jaydenkerr.restorey`; restic identifier `com.jaydenkerr.restorey.restic`. Debug builds insert `.dev` after `restorey` in every one of these.
- Team `X72LEXP4DY`, read from the gitignored `Config/Local.xcconfig` (`#include?` from `Config/Base.xcconfig`). Never commit a team ID override or a signing secret.
- restic is pinned to 0.19.1 and rest-server to 0.14.0. Both are downloaded from the upstream GitHub releases into the gitignored `vendor/` and checked against the release `SHA256SUMS`. Never use Homebrew binaries. restic is re-signed with the app identity and hardened runtime at build time.
- Agent plist: `BundleProgram`, `MachServices` (both services), `KeepAlive` true, `RunAtLoad` true, **`ProcessType` `Standard`** (spike, decided). Never `Adaptive` or `Background`.
- Keychain: `kSecUseDataProtectionKeychain: true`, `kSecAttrAccessibleAfterFirstUnlock`, and the access group above. Never drop `kSecUseDataProtectionKeychain`, in tests either (spec §10).
- Secrets (repository password, backend keys, raw environment values, check-in URL) live only in the keychain. They never go in config, logs, the agent's own environment, or a file. S3 and B2 keys reach restic only through `credential_process`.
- Every restic call passes `--json`, `--cache-dir <Caches>/<id root>/restic`, and `RESTIC_PROGRESS_FPS=2`. `backup`, `forget` and `snapshots` pass `--host <plan.hostLabel>`. Backups are tagged `restorey:<plan id>`. `forget` uses `--host <label> --tag restorey:<plan id> --group-by host,paths,tags`. Maintenance commands use `--retry-lock 5m`. Never call `restic unlock --remove-all`. Never `restic init` except on an explicit create action.
- Retention defaults: `--keep-hourly 24 --keep-daily 30 --keep-weekly 52 --keep-monthly 120`. "No successful backup" alert threshold: 3 days. Battery threshold: 20 %. Pause auto-resume: 1 h. SIGINT, then SIGKILL after 10 s. Log retention: 400 days.
- Exit codes (spec §8): 0 success · 3 warning with count · 10 and 12 configuration errors that stop the plan and alert at once · 11 reschedule · 130 after our own SIGINT is paused or cancelled, otherwise failure · anything else is failure.
- All timestamps are stored in UTC. Australian English in all UI text, logs meant for people, and docs.
- Commits follow the owner's rule: update the README and any relevant docs in the same commit. No `Co-Authored-By` or session trailers. `TODO.md` stays gitignored.
- Builds and signed tests run on this Mac (not birdseye). GitHub CI runs the unsigned build and the `RestoreyCore` tests.

## Review Focus

1. **A source path that starts with `-`, or contains spaces or non-ASCII characters** (e.g. `~/Documents/-drafts`, `~/Café Notes`). People expect it to be backed up, not read as a restic flag or split. Task 4 puts `--` before the paths, and its test pins this.
2. **A config or state file that is corrupt or written by a newer Restorey.** People expect their plans to survive. The agent must refuse to load, keep the file untouched and report it, never overwrite it with an empty config. This is tested in Task 3.
3. **The agent dies or is restarted during a run** (crash, update drain timeout, logout). People expect the next start to record that run as interrupted, not as success or failure, to clear its stale lock with a plain `unlock`, and to retry soon. This is tested in Task 14.
4. **A clock or time zone change** (travel, DST, a manual clock change). People expect hourly to stay hourly and the "no backup in 3 days" alert to be neither early nor silent. Schedules use UTC instants and elapsed intervals, and Task 8 tests both a time zone change and a backwards clock jump.
5. **A repository password or key with spaces, quotes, a trailing newline or non-ASCII characters.** People expect it to work byte for byte. Task 13 tests the helper end to end with `pa ss"wörd\n`-style values.
