# v0.1 UI implementation plan (plan 2 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the developer window with the real Restorey app — first-run setup, the menu bar in every state, the Settings window and the recovery kit — so the owner can move their Mac's real backups onto Restorey: "setup works end to end and backups just run quietly."

**Architecture:** The engine (merged in PR #1) stays the single owner of config, secrets and runs; the app changes it only over XPC. This plan first adds the engine calls and status fields the screens need (Tasks 1–5), then builds the screens in the app (Tasks 6–15). Everything the screens decide — what the menu shows, which setup step comes next, what the recovery kit says — is a pure value type in `RestoreyCore/Sources/RestoreyCore/App/` with Swift Testing tests, because the app target has no test target and its views stay thin. Views are SwiftUI hosted in AppKit windows; the status item and the main menu are AppKit.

**Tech Stack:** as plan 1 (Swift 6.4, macOS 27.0, Xcode 27.0, XcodeGen 2.46.0, Swift Testing, `NSXPCConnection`, ServiceManagement), plus SwiftUI, LocalAuthentication, CoreWLAN, CoreLocation, PDFKit/`NSPrintOperation`.

**Spec:** `docs/superpowers/specs/2026-11-12-restorey-v0.1-ui-design.md` ("the UI design", binding for v0.1), which narrows the product spec `docs/superpowers/specs/2026-11-09-restorey-design.md`. Mockups: `docs/mockups/v0.1-setup-flow.html`, `v0.1-settings.html`, `v0.1-menu-states.html`, `menubar-and-restore.html`. Rulings R1–R78: `docs/v0.1-rulings.md`. Live results: `docs/v0.1-measurements.md`.

## Scope

**In this plan:** everything in the UI design §4–§8.

**Not in this plan:** the restore window (v0.2), cold plans (v0.3), ntfy/Pushover/webhooks and test restores (v0.1.x), the signed DMG and release automation (plan 3). Plan 1 also listed "Copy as restic command", "Send diagnostic report" and the Settings cache size with Clear for plan 2; the UI design doesn't include them, so they move to plan 3's list (Ruling P2-1 below — the Restore Files sheet already gives the restic commands).

## Decisions made in this plan (builder's calls, UI design §10)

- **P2-1** Copy as restic command, diagnostic report and cache size move to plan 3 (above).
- **P2-2 Probe before create or adopt.** Setup step 2's "Check" saves the plan (kit unconfirmed, so it never runs) with its secrets, then calls a new `probeRepository`. Create and adopt stay as they are. Leaving setup with Cancel deletes that plan; quitting leaves it unfinished (UI design §5).
- **P2-3 Unfinished vs needs new kit.** A new `Plan.setupCompletedAt: Date?` is set by the first `confirmRecoveryKit` and never cleared. Kit unconfirmed and `setupCompletedAt == nil` is "Setup not finished"; kit unconfirmed after setup is "New recovery kit needed".
- **P2-4 History** comes from a new `history(planID:)` call returning `PlanRunHistory.recent` (the 50 newest records per plan); `PlanStatus` gains `lastBackup: RunRecord?` (newest backup whose outcome is success, unchanged or warning) so the menu can say "Backed up at <time>" whatever ran since.
- **P2-5 Secrets reach the app** through a new `recoveryKit(planID:)` call that returns the plan's secrets, served only to the app's code-signed connection. The app asks for Touch ID or the login password (`LAContext.evaluatePolicy(.deviceOwnerAuthentication)`) before every call and holds the reply only while the sheet is open.
- **P2-6 Mac-wide network settings** live in `config.json` beside the plans (`ConfigFile.network: NetworkSettings`, schema 3). Migration 2→3 sets `skipOnConstrainedNetwork` to true if any plan had it on (the default) and removes the per-plan field.
- **P2-7 Upload limits:** a backup to a networked repository gets `--limit-upload` = the smaller of the plan's limit and the Mac-wide limit divided by the number of networked backups running when it starts (counting itself). restic can't change the limit mid-run, so a run keeps the value it started with.
- **P2-8 Wi-Fi names** are read by the agent (it runs the preflight) with `CWWiFiClient.shared().interface()?.ssid()`. The agent requests Location authorisation over XPC (`requestLocationPermission`), like notifications, when the first name is added. The agent's Info.plist gets `NSLocationUsageDescription`. A nil SSID (no permission, or not on Wi-Fi) never skips. Task 3 verifies the prompt and the SSID read live, because the agent is a background helper app.
- **P2-9 Repository size:** a new `ResticOperation.stats` (`restic stats --mode raw-data --json`) runs in the plan's queue after each prune and after adoption; its total is stored as `PlanRunHistory.repositorySize: RepositorySize?` (`bytes`, `measuredAt`) and sent in `PlanStatus`.
- **P2-10 Setup progress** is app-side: `SetupProgress` (plan ID and step) in `UserDefaults`, no secrets. The app reopens setup at launch while any plan has `setupCompletedAt == nil` or no plan exists.
- **P2-11 Full Disk Access in setup** uses a new `probeFullDiskAccess` call (the agent's own probe, product spec §5.7) on window activation and every 2 s while the step is shown.
- **P2-12 Deleting a plan removes its run-log folder** (`runs/<planID>`): the confirmation already says its history is removed (TODO from the 24 h observation).
- **P2-13 Forget logs** keep a one-line summary (kept and removed counts per group, removed snapshot IDs) instead of restic's full `forget --json` line (TODO, 24 h observation).
- **P2-14 Schedule drift:** the scheduler sleeps until the earliest due time (capped at the 60 s tick) instead of finding due plans on a fixed 60 s tick (TODO, optional item; cheap with `SchedulerCore` already computing due times).
- **P2-15 The iCloud skipped-files line is left out in v0.1** (UI design §8 allows it; counting cloud-only files is v0.1.x).
- **P2-16 Open at login** registers the app itself with `SMAppService.mainApp` (default on, set in setup's permissions step).

## Global Constraints

Everything in plan 1's Global Constraints still holds (identities, team, pinned binaries, agent plist, keychain attributes, secrets only in the keychain, restic flags, exit codes, UTC, Australian English, commit rules, builds on this Mac). In addition:

- UI text follows the mockups' wording and Australian English. Menu wording: "Backed up at <time>", "Paused", "Resumes by itself at <time>", "Full Disk Access is missing", "The background agent isn't running", "Notifications are off — Restorey can't alert you", "No off-Mac monitoring", "Setup not finished", "New recovery kit needed", "Finishing the current backup before updating the agent". Never "Failed" for a paused, skipped or system-stopped run.
- The icon shows the worst state across plans in this order: error > warning > paused > backing up > OK. Error is the only filled icon.
- The menu updates while open (product spec §5.1).
- Secrets are never kept in app state after the sheet or step that needed them closes, never logged, and never written by the app to disk except where the user picks a save location for the recovery kit.
- The helper's code-signing requirements are not relaxed (owner). Tests and `ci.sh` never touch the real identity (R66).
- The developer window stays in Debug builds only.
- New XPC calls follow plan 1's pattern: Codable `Data` payloads, a user-facing error string, a typed wrapper in `AgentConnection`. Bump `HelloRequest`/`HelloReply` protocol version so an old agent is restarted after the update.

## Review Focus

1. **Granting Full Disk Access quits the app mid-setup.** People expect to land back on the permissions step with Full Disk Access ticked and nothing re-entered. Task 10 tests `SetupProgress` restore after a relaunch; Task 15's live check covers the real quit.
2. **A plan whose kit was never confirmed, or needs re-confirming.** People expect "Setup not finished" or "New recovery kit needed", never silence and never "Failed", and setup to reopen at the right step. Task 7 tests both menu presentations; Task 1 tests `setupCompletedAt`.
3. **The agent is unreachable while a backup runs (R68), or an old agent's late reply arrives after an update (R76).** People expect "Backing up (agent not answering)" rather than "unreachable", and no flash of old status. Task 8 tests both through `MenuPresentation`/`AgentSupervisor` inputs.
4. **Secrets with spaces, quotes, non-ASCII characters or a trailing newline** in setup, the recovery kit and the Restore Files commands. People expect them byte for byte, and shell-quoted in commands. Task 13 tests the restore command builder with `pa ss"wörd'\n`.
5. **A Wi-Fi name, upload limit or file-type entry the user mistypes** (empty, spaces only, a duplicate, 0 or negative limit). People expect it refused with a reason, not saved. Tasks 2 and 9 test validation.
