# v0.1 engine: alpha run and measurements

The v0.1 engine's alpha ran on the owner's Mac on 11 November 2026. This file records what was measured and checked, and
what changed as a result. All times are UTC.

- **Mac:** Apple silicon; macOS 27.2.
- **Builds:** development builds 6–10 of `RestoreyDev.app`: build 6 is commit `09867b3`, build 7 `b8d6f4c`, build 8
  `cff91a1`, build 9 `fd0d403` and build 10 `87d9254` (after the final review's fixes).
- **restic:** 0.19.1, bundled.
- **Repository:** Backblaze B2 through its S3 endpoint (`s3.us-west-001`), in the test bucket `restorey-test`, under the
  prefix `alpha-downloads`.
- **Check-ins:** a healthchecks.io check.

| 02:54:00 | catch-up (network back) | success | 742 B | 5.7 s |
| 03:09:55 | retry (after `kill -9`) | success | 742 B | 5.4 s |
| 04:11:00 | scheduled | success | 748 B | 7.2 s |

An hourly run over an unchanged folder reads no file contents. restic compares size, modification time and inode, then
records a snapshot of about 600 bytes after compression.

The runs still make a new snapshot rather than an "unchanged" result. restic stores the metadata of every parent folder
of a source, and the home folder's modification time changes all day. `restic diff` between two of these snapshots shows
only `U /Users/` and `U /Users/kerrj/` (748 B of trees, no files). Ruling R65 drops the spec's "Up to date — no changes"
idle state for this reason; `--skip-if-unchanged` stays for sources whose parents are stable, such as a whole drive.

## Full Disk Access survey (Task 18 Step 1)

Command: `restic backup --dry-run --json` over `/Users/kerrj` with the v0.1 default exclusions and
`--exclude-cloud-files`, from a shell with Full Disk Access, into a throwaway repository.

The first attempt ran at background priority (`taskpolicy -b`, Darwin priority 4). It read 903 files in 45 minutes, so
it was stopped. This matches the Task 4 spike finding that the background band makes backups crawl. The second run used
the utility QoS that the agent uses.

| Measure | Result |
|---|---|
| Time | 03:41:00–04:56:32, 75.5 min; exit 3 (some files could not be read) |
| Size | 2,269,914 files and 422,008 folders, 505.0 GB read |
| A first full backup would add | 415.5 GB of unique data, 266.7 GB after compression (≈ 7½ hours at 10 MB/s) |
| CPU | about 270 % while reading many small files, about 80 % on large ones; about 110 MB/s on average |
| Cloud-only files skipped | **restic reports no count**: `--exclude-cloud-files` skips them silently, so a "1,204 iCloud files were skipped" line needs Restorey's own count |

The run logged 272 errors. They fall into three groups.

| Cause | Errors | Where |
|---|---|---|
| Other filesystems mounted inside the home folder | 255 | `~/OrbStack`: OrbStack's NFS view of containers; mostly debugger FIFOs, 106 EPERM and 1 ENOENT. `~/Library/Developer/CoreDevice/DeviceFS`: an fskit mount of connected iPhones; EINVAL, ENOTDIR, ENOSTR, EFBIG. |
| Files that vanished mid-scan | 11 | FileProvider `wharf/delete`, a Spotlight journal |
| Refused even with Full Disk Access | 3 | `~/Library/Application Support/FileProvider/*/wharf/tombstone` (the host and a simulator); `~/Library/Group Containers/group.com.apple.secure-control-center-preferences/…/…av.plist` |

There was also one EOVERFLOW from a simulator file.

Without exclusions for these, every hourly run of a home-folder plan would end as "some files skipped". Ruling R64 adds:
- `--one-file-system`. restic allows the device of every source, so a drive listed as a source is still backed up.
- the FileProvider `wharf` and secure-control-center paths
- the Time Machine standard and per-item exclusions found by probing with `tmutil isexcluded`
- an editable file-type list that excludes disk images and VM images by default

## Findings that changed the code

These are rulings R57–R74 in the plan's ledger:
- **R57:** no check-in `/start` ping.
- **R58, R63:** an interrupted backup retries after 15 minutes and is labelled `retry`.
- **R59, R62:** Resume starts a backup, even while the paused run is still stopping.
- **R60:** the network coming back re-runs plans skipped for no network.
- **R61:** the agent carries the app's display name.
- **R64:** the default exclusions above.
- **R65:** no "Up to date — no changes" state.
- **R66:** only the launchd job runs as the agent. Found when `ci.sh`'s hosted-test host — a copy of the agent launched by
  XCTest — ran the full start-up against the real Debug identity: it wrote to the real `agent.log`, failed to take the
  Mach services but carried on, and wrote failed `unlock` records into the real `state.json` (no restic in the test
  bundle, so no repository was touched). The agent now starts only when `XPC_SERVICE_NAME` equals its label.
- **R67, R73, R74:** launchd's SIGTERM at logout, restart or shutdown is routine: restic gets SIGINT (SIGKILL after
  2.5 s, a pause's too) and the run is recorded "stopped by the system" with no alert, inside launchd's exit timeout,
  which is 5 s for a LaunchAgent on macOS 27 (`launchctl print` shows `exit timeout = 5`), not the 20 s first assumed.

## Carried to plan 2 or the final review

- The Developer window takes text only through real key presses. Accessibility value writes never reach the SwiftUI model, which matters for VoiceOver and other assistive input.
- The message shown when a changed password asks for the recovery kit again reads "before its first backup".
- Upload speed has to be derived from `bytes_done` over time; restic reports no rate.
- The helper's full refusal chain (real XPC, audit-token signature check, parent-process check) is now checked by the
  live script `scripts/check-helper-refusal.sh`, not by CI. Run it after installing a development build.
- `scripts/install-dev.sh` fails to relaunch the app (`_LSOpenURLsWithCompletionHandler` −600).
- A free-space check must use `volumeAvailableCapacityForImportantUsage`. `df` showed 18 GB free while Finder showed 139 GB, because local Time Machine snapshots count as purgeable.
